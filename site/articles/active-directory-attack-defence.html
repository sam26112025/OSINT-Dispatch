Active Directory Attacks and Defences: What Every Indian Security Team Must Know

File No.IGRS-060/2026
SubjectCommon Active Directory attack patterns, detection methods, and priority hardening steps for Indian organizations
CategoryThreat Intelligence
AuthorManuj Kumar Pandey
Published2026-06-04
Reading time7 minutes

Active Directory is the authentication backbone of most Indian enterprise environments — and the primary target of attackers who have established a foothold. The most important attacks and how to defend.

Why Active Directory is the prize

Active Directory manages authentication and access control for every user account, computer, and server in a Windows domain network. Compromising Active Directory gives an attacker control over every resource in the domain. The overwhelming majority of Indian enterprise and government Windows environments use Active Directory, making AD attack and defence one of the highest-priority knowledge areas for Indian security teams.

Kerberoasting

Any domain user can request a Kerberos service ticket for any service account that has a Service Principal Name (SPN) registered. The ticket is encrypted with the service account's password hash. Attackers request these tickets and crack them offline. Service accounts often have weak passwords and rarely rotate. Defence: use long, complex, regularly rotated service account passwords; use Group Managed Service Accounts (gMSAs) for automatic password rotation; monitor Event ID 4769 for unusual encryption types (RC4) which may indicate Kerberoasting in progress.

Pass-the-Hash

Windows stores NTLM password hashes in memory (LSASS process) and uses them for authentication. Attackers with local administrator access extract these hashes and use them to authenticate to other systems without knowing the plaintext password — the hash is the credential. Defence: enable Windows Credential Guard to prevent LSASS dumping on modern systems; restrict local administrator accounts rigorously using LAPS (Local Administrator Password Solution) to randomize local admin passwords; monitor Event ID 4624 Type 3 with NTLM from unusual sources.

DCSync

An account with Directory Replication permissions can request that domain controllers replicate credential data, effectively pulling all password hashes from the domain. This abuses legitimate replication functionality using compromised privileged credentials. Defence: audit which accounts have replication permissions (should be only domain controllers and specific backup accounts); alert on unexpected replication requests.

The most impactful single defensive step: Enable the Protected Users security group for all privileged accounts. This prevents credential caching, forces Kerberos with no NTLM fallback, and limits ticket lifetimes — significantly raising the cost of credential-based attacks against your most privileged accounts.

Tier-based administration

The most effective structural defence is tiered administration: Tier 0 (Domain Controllers — managed only by dedicated Tier 0 admin accounts that never log into lower-tier systems); Tier 1 (servers); Tier 2 (workstations). This prevents credential theft from workstations, where most initial compromises occur, from enabling direct access to domain controllers.
