DNS Investigation: Mapping Digital Infrastructure

The Domain Name System (DNS) is the internet's address book, translating human-readable domain names into IP addresses. For investigators, DNS is a treasure trove of intelligence — revealing infrastructure, connecting related domains, exposing malicious operations, and tracing the digital footprint of threat actors. DNS investigation is a core OSINT skill. This guide covers the complete methodology.

Understanding DNS Records

Record TypeWhat It Reveals
A / AAAAIPv4/IPv6 address of the domain
MXMail servers handling email
NSName servers managing the domain
TXTVerification records, SPF, DKIM
CNAMEAliases pointing to other domains
SOAAuthority and administrative info

Basic DNS Investigation Tools

The foundational tools for DNS investigation include:

  • dig / nslookup — command-line DNS queries
  • DNSDumpster — visual DNS mapping and discovery
  • SecurityTrails — historical and current DNS data
  • VirusTotal — DNS resolutions and reputation
  • MXToolbox — comprehensive DNS and mail diagnostics

Passive DNS: The Historical Record

Passive DNS is one of the most valuable investigative resources. It records historical domain-to-IP mappings over time, allowing investigators to see what a domain resolved to in the past — even after records change. This is invaluable for tracking infrastructure evolution, finding related malicious domains that once shared an IP, and uncovering an attacker's broader operation despite their attempts to cover tracks.

Reverse DNS and IP Pivoting

Reverse DNS lookups find what domains resolve to a given IP, enabling powerful pivoting. When multiple malicious domains share an IP address, they are likely part of the same operation. By pivoting between domains and IPs — finding all domains on a malicious IP, then all IPs those domains used — investigators map entire attacker infrastructure networks from a single starting point.

Investigating Malicious Infrastructure

DNS investigation exposes malicious infrastructure through several signals:

  • Multiple malicious domains sharing an IP or name server
  • Common registration patterns across domains
  • Matching TXT or SOA records linking domains
  • Recently registered domains used in attacks
  • Fast-flux DNS rapidly changing IPs to evade blocking

Subdomain Discovery

Finding a domain's subdomains reveals its full attack surface and infrastructure. Techniques include certificate transparency logs (crt.sh), DNS brute-forcing, passive DNS data, and search engine enumeration. Subdomains often expose development servers, admin panels, and forgotten infrastructure that the main domain conceals — valuable both for security assessment and investigation.

Certificate Transparency and DNS

Certificate transparency logs, searchable via crt.sh, complement DNS investigation by revealing all SSL certificates issued for a domain and its subdomains. Since certificates are issued for specific hostnames, these logs expose subdomains and related infrastructure. Combining certificate transparency with passive DNS provides a comprehensive view of an entity's digital footprint.

DNS in Phishing and Fraud Investigation

DNS investigation is central to phishing and fraud cases. Analysing a phishing domain's DNS reveals its hosting, its mail configuration, related domains in the campaign, and registration details. Newly registered domains, suspicious name servers, and infrastructure shared with known-bad domains all flag fraudulent operations. The DNS trail frequently connects a single phishing site to an entire campaign.

Detecting DNS-Based Attacks

Beyond investigating domains, DNS analysis detects attacks: DNS tunnelling (data exfiltration hidden in DNS queries), fast-flux networks (rapidly changing infrastructure), domain generation algorithms (malware-generated domains), and cache poisoning. Monitoring DNS query logs for these patterns is an important defensive and investigative capability.

Legal and Practical Considerations

DNS investigation primarily uses public data and is generally unrestricted. WHOIS data, while increasingly redacted for privacy, still provides registration insights, and legal process can obtain registrant details from registrars where needed. For evidence purposes, DNS findings should be documented with timestamps and, where used in court, supported by proper certification. The largely open nature of DNS data makes it an accessible yet powerful investigative resource.

Building DNS Investigation Skills

Mastering DNS investigation requires understanding record types, learning to pivot between domains and IPs, leveraging passive DNS and certificate transparency, and recognising the infrastructure patterns that connect malicious operations. For Indian investigators tracing phishing campaigns, fraudulent platforms, and threat actor infrastructure, DNS investigation transforms a single domain or IP into a map of an entire operation — making it an indispensable technique in the OSINT toolkit.

Frequently Asked Questions

How do you investigate a domain using DNS?
DNS investigation examines A, MX, TXT, NS, and CNAME records, historical DNS data, reverse DNS lookups, and passive DNS databases. Tools like dig, dnsdumpster, SecurityTrails, and VirusTotal reveal infrastructure and related domains.
What is passive DNS and why is it useful?
Passive DNS records historical domain-to-IP mappings over time. It is useful for tracking infrastructure changes, finding related malicious domains sharing an IP, and uncovering an attacker's broader footprint even after records change.
How can DNS records reveal malicious infrastructure?
Shared IPs, common name servers, similar registration patterns, and matching TXT records can link malicious domains. Pivoting on these data points through passive DNS reveals entire attacker infrastructure networks.
