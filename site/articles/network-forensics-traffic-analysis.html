Network Forensics: Reading Packet Captures Like an Investigator

File No.IGRS-029/2026
SubjectPractical guide to PCAP analysis for incident investigation and intrusion reconstruction
CategoryDigital Forensics
AuthorManuj Kumar Pandey
Published2026-05-17
Reading time6 minutes

Network traffic doesn't lie. A properly captured PCAP can reconstruct exactly what happened during an intrusion, data exfiltration, or attack. How to read it.

What network forensics tells you

When an endpoint is compromised, the attacker must communicate — with command and control infrastructure, with lateral movement targets, with exfiltration endpoints. That communication traverses the network and, if captured, provides an objective record of what occurred that is independent of the attacker's ability to tamper with endpoint logs. Network forensics reconstructs the who, what, when, and where of network-layer activity with a precision that endpoint-based evidence alone cannot match.

Capture points and their limitations

The most useful capture points for forensic network analysis are: the network perimeter (capturing all traffic crossing the firewall — shows external communication but not internal lateral movement), core switches (capturing inter-VLAN traffic — reveals lateral movement and internal data transfers), and endpoint-level captures (using tools like Wireshark or tcpdump directly on hosts — highest granularity but requires pre-positioned capability or memory forensics post-incident). Full packet capture at scale requires significant storage — a realistic deployment strategy involves capturing full packets at perimeter choke points and collecting only metadata (NetFlow/IPFIX) from internal segments.

Wireshark as an investigation tool

Wireshark is the primary tool for investigative PCAP analysis. Key workflows for incident investigation: follow TCP stream (reconstructs the full conversation between two endpoints, including transferred content for unencrypted protocols); protocol statistics (shows the volume distribution across protocols — unusual proportions suggest specific attack types); display filters (isolates traffic by IP, port, protocol, or content patterns — the most powerful investigation tool in Wireshark); and export objects (extracts files transferred over HTTP, SMB, FTP directly from the capture for analysis).

Identifying attack patterns in PCAPs

Common attack patterns have distinctive network signatures. Port scans appear as rapid sequential SYN packets to multiple ports with mostly SYN-ACK or RST responses. Brute force authentication shows repeated connection attempts to authentication services (SMB port 445, RDP port 3389, SSH port 22) with authentication failure responses. C2 communication often shows regular, periodic outbound connections to unusual external IPs — a beaconing pattern that stands out against normal traffic baselines. Data exfiltration appears as unusually large outbound transfers, often to cloud storage services, file transfer sites, or unusual IPs, particularly during off-hours.

Encrypted traffic challenge: TLS encryption prevents content inspection of most modern traffic. However, metadata — connection frequency, timing, volume, destination, and TLS handshake characteristics — is still visible and often sufficient to identify malicious communication patterns.

Documentation for legal use

Network forensic evidence must be documented carefully for use in legal proceedings. The chain of custody for capture files must be established — who captured the traffic, on what equipment, using what software version, with what configuration. Hash values of the raw PCAP files must be computed immediately after capture and recorded. The analysis methodology — what filters were applied, what conclusions were drawn and from which packets — must be documented in sufficient detail that another examiner could reproduce the analysis and reach the same conclusions.

Frequently Asked Questions

What is network traffic analysis?
Network traffic analysis examines captured packets and flow data to detect intrusions, investigate incidents, and reconstruct activity. It reveals communication between hosts, data transfers, and malicious patterns.
What tools are used for network forensics?
Key tools include Wireshark for packet analysis, Zeek for network metadata, NetworkMiner for file reconstruction, Suricata for IDS, and tcpdump for capture. NetFlow analysis tools help with large-scale traffic.
How long are network logs retained in India?
Under CERT-In directions, organizations must retain ICT system logs for 180 days. ISPs maintain subscriber-IP mapping for at least 12 months. These logs are accessible to law enforcement through proper legal process.
