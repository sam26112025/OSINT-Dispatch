Reading Email Headers: How to Trace the Origin of Any Email

File No.IGRS-033/2026
SubjectStep-by-step guide to email header analysis for origin tracing and phishing investigation
CategoryOSINT Fundamentals
AuthorManuj Kumar Pandey
Published2026-05-29
Reading time5 minutes

Email headers contain the full routing history of every message. Reading them reveals the true sender origin — even when the displayed address is forged.

Why headers matter

The "From" field in an email is trivially easy to forge — any mail server can be configured to claim any sender address. Email headers, by contrast, record the technical routing history of a message as it passes between mail servers, and this record is generated by infrastructure that the attacker does not control. While sophisticated attackers can manipulate some header content, the "Received" chain — the sequence of servers that handled the message — typically contains authentic origin information that is the foundation of email tracing.

How to access full headers

In Gmail: open the message, click the three-dot menu (⋮), select "Show original." In Outlook: open the message, File → Properties → Internet headers. In Apple Mail: View → Message → All Headers. The raw header text is typically 20–50 lines of technical routing information. Copy this text for analysis.

Reading the Received chain

The "Received" headers are the most important. They are added in reverse order — each mail server adds its entry at the top as the message passes through. So the bottom Received header is closest to the original sender. Each Received line shows: the IP address of the sending server, the hostname it claimed, the receiving server's name, and a timestamp. Reading from bottom to top gives you the message's journey from sender to your inbox.

The bottom-most "Received: from" entry that is not your own mail infrastructure is the first external hop — the server that injected the message. The IP address in that line is the most valuable piece of forensic information in the header. Run it through ipinfo.io, AbuseIPDB, and Shodan to identify the hosting provider, geographic origin, and any associated abuse reports.

Authentication headers

Modern email includes authentication results that show whether the message passed SPF, DKIM, and DMARC checks:

  • SPF pass: The sending server was authorized by the domain's DNS record to send on its behalf — reduces likelihood of spoofing but does not prove legitimate content
  • DKIM pass: The message was cryptographically signed by the sending domain — stronger authentication; a DKIM pass means the message body and key headers were not modified in transit
  • DMARC fail: The message failed the domain's authentication policy — a strong indicator of spoofing or phishing when combined with a legitimate-looking From address
A phishing email claiming to be from your bank that shows SPF fail and DMARC fail in its authentication headers is definitively not from your bank. These authentication results, preserved in the header, are powerful evidence in phishing investigation reports.

Practical analysis tools

MXToolbox Email Header Analyzer and Google Admin Toolbox (toolbox.googleapps.com/apps/messageheader/) parse raw headers into human-readable form, visualizing the routing chain and highlighting anomalies. For bulk header analysis in phishing investigation, PhishTool provides structured header analysis with threat intelligence integration.
