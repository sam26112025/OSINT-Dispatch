ServiceNow Data Breach: How a Silent Patch Left Enterprises Unaware for Four Days

File No.IGRS-065/2026
SubjectAnalysis of the ServiceNow unauthenticated API breach, its disclosure timeline, and enterprise response guidance
CategoryIncident Response
AuthorManuj Kumar Pandey
Published2026-06-12
Reading time7 minutes

ServiceNow disclosed a security incident in which attackers used an unauthenticated API endpoint to query customer instance data. The four-day gap between patch and public disclosure raises serious questions about enterprise breach notification obligations.

What happened

ServiceNow, the enterprise IT service management platform used by a significant portion of the Fortune 500, disclosed that attackers exploited a misconfigured API endpoint to access data stored in customer instances without requiring any credentials. The company applied a security patch to hosted customer instances on June 5, 2026 but did not publish a public advisory until June 9, 2026 — a four-day gap that has drawn criticism from security professionals and compliance teams.

The advisory itself was placed behind ServiceNow's customer support login portal, meaning only existing customers with portal access could see it. Organizations subject to regulatory breach notification requirements — GDPR's 72-hour window, SEC cybersecurity disclosure rules, or HIPAA Business Associate Agreement obligations — cannot start their notification clock without a signal that a breach occurred. A silent patch provides no such signal.

The technical root cause

The vulnerability appears to have been a Scripted REST API endpoint — specifically /api/now/related_list_edit/create — that was configured with requires_authentication=false. This meant the endpoint accepted and processed requests from anyone on the internet without requiring a valid session token, password, or any form of credential check. Attackers exploited this window to query "instance tables" — the structured data stores within each customer's ServiceNow environment.

ServiceNow instances typically contain highly sensitive enterprise data: IT support tickets (which can contain credentials and system architecture details), employee records, internal documentation, asset inventories, security incident reports, workflow configuration, and corporate system credentials embedded in automation scripts.

Key disclosure concern: Community reports on Reddit and security forums claim that a customer security team reported the vulnerability to ServiceNow around April 7, 2026 — approximately two months before the June 5 patch. ServiceNow reportedly classified the issue as non-urgent initially, with remediation scheduled for a future planned release. If accurate, this significantly extends the window during which the vulnerability may have been exploitable.

How to determine if your organization was affected

ServiceNow has stated that it opened support cases with affected customers. If your organization has not received a support case from ServiceNow regarding this incident, the company says you are not believed to be affected. However, given the transparency concerns around the disclosure itself, security teams should independently verify by:

  • Reviewing ServiceNow access logs for the period April–June 2026 for unusual API calls to the /api/now/related_list_edit/create endpoint
  • Checking for anomalous data query volumes from unauthenticated or unexpected source IPs in that period
  • Contacting your ServiceNow account representative directly for written confirmation of impact status
  • Logging into the ServiceNow customer support portal and reviewing support bulletin KB3067321

Regulatory implications for Indian organizations

Indian organizations using ServiceNow that store personal data of Indian users in their instances have obligations under the DPDP Act 2023 and CERT-In's 6-hour incident reporting directions. If personal data was accessed during this incident, the CERT-In notification clock starts from the moment the organization becomes aware — which for ServiceNow customers who received a support case may be June 9, 2026 when the advisory was shared. Organizations should document their awareness date carefully and consult legal counsel on notification obligations.

Broader lesson: the silent patch problem

The ServiceNow incident illustrates a systemic problem in enterprise software security: vendors applying security fixes without simultaneously notifying customers in a clear, accessible way. A patch that closes a vulnerability is valuable. A patch applied without customer notification — when exploitation has already occurred — is a transparency failure that compounds the original security failure. Enterprises should require vendors to contractually commit to timely, clear breach notification as part of their SaaS procurement process.
