Why a widget, not just a raw API

For most websites and blogs, an embeddable widget is a better fit than a raw API. It works without any backend code, it runs entirely in your visitor's browser, and it never routes your users' lookups through a third party's logs. Because each query is made from the end-user's own browser to the public upstream services — the same way the tools work on igrs.xyz — the load is naturally distributed and no shared API quota is consumed on your behalf.

Privacy & data handling

The IP Lookup widget queries public network-intelligence data and does not transmit any personal data you enter beyond the IP address being looked up. The Breach Check widget uses the k-anonymity model for passwords: a password is hashed locally and only the first five characters of the hash are ever sent, so the full password and its hash never leave the browser. Email breach lookups query an external breach-intelligence service directly; users should only check addresses they own or are authorised to investigate.

Attribution & fair use

These widgets are offered free for lawful, authorised use — security awareness, research, education, and investigation within the scope of your authority. The only condition is that the “Powered by IGRS” link remains visible. Underlying network, geolocation, and breach data are provided by third-party services (ipapi.is, XposedOrNot, Have I Been Pwned); IGRS is not affiliated with them, and high-volume or commercial users should review and subscribe to those providers directly.
