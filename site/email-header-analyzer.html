How to read an email header in an investigation

Email headers are the metadata trail every message carries. Read from the bottom up, the Received lines record each mail server that handled the message — the lowest one is usually closest to the true origin, while the top is your own inbox. The analyzer reverses and orders these hops so you can see the path and the time spent at each stage; unusual gaps or a first hop from an unexpected network are worth a second look.

Authentication: SPF, DKIM and DMARC

These three checks tell you whether the sending server was authorised and whether the message was tampered with. SPF validates the sending IP against the domain's published senders; DKIM verifies a cryptographic signature over the content; DMARC ties the two to the visible From domain and states a policy. A fail on any of these, especially DMARC, is a strong signal of spoofing or forwarding abuse — though legitimate mailing lists and forwarders can also break SPF, so weigh it alongside the other evidence.

Spoofing red flags

The tool flags common impersonation patterns: a Return-Path or Reply-To domain that differs from the visible From domain, a display name that mimics a brand while the real address does not, and outright authentication failures. None of these alone proves malice, but together they build the evidence chain. For attribution, the originating IP can be profiled further with the IGRS IP Lookup, and any finding meant for an FIR should be preserved with a certificate under Section 63 of the Bharatiya Sakshya Adhiniyam, 2023.
